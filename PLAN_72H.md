# 72-Hour Plan (T+0 = problem published)

## Hours 0-4: Decide
- Read brief twice. Fill Section 10 logic chain (one page). Pick ONE narrow user + problem.
- Assign roles: ML, backend/API, frontend, docs/deploy (everyone can explain everything).
- Create public repo, first commit.

## Hours 4-12: Data + baseline
- Adapt data generator, document assumptions.
- Simple rule baseline + first model. Hold out a clean test set.

## Hours 12-30: Core product
- Model + explanation (SHAP/rule trace) + business rules separate.
- API endpoints, then UI for one end-to-end flow.
- Commit step by step (small commits, clear messages).

## Hours 30-48: Deploy early
- Live URL working by hour ~40. Fairness check across groups. Human review path.

## Hours 48-60: Harden
- Tests, README completed from template, impact metric vs baseline.
- Keep code modular so on-site updates are easy.

## Hours 60-68: Deliverables
- Record demo video (flow, AI parts, real-life value). Write report.

## Hours 68-72: Submit
- Fresh-clone test following README. Submit repo, video, report with buffer. No late submissions.

## Before on-site (Oct 7)
- Bring laptops, chargers, hotspot, ID. Everyone rehearses explaining design. Expect new requirements: commit often, deploy fast.
